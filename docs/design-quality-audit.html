Design quality audit/ Noise Lab console/ 20 Aug 2026

Declared,
not adopted

The design system asked for in the last audit was built — tokens, primitives, a lint script. Then the app kept routing around it. This is what the code actually does now, measured rather than estimated, and the work that follows from it.

The previous audit asked for five phases. Phases 1 and 2 shipped, and shipped well: there is a real token block, eight extracted primitives in web/app/ui/, and zero hex literals outside :root — precisely the acceptance criterion that was set. That deserves saying plainly.

Phases 3, 4 and 5 did not happen. What happened instead, across roughly thirty commits, was a run of one-line nudges: Capitalize 'Synced' in Queue sync caption. Vertically center Library header sync caption. Center Library header sync caption. Tighten Library header whitespace to match Queue. Four separate pull requests hand-aligning two captions that the last audit had already said should be one component.

The system exists as a document and is bypassed as a practice — and the guardrail that was built enforces the half of the rule that was already satisfied.

check-tokens.mjs verifies that declared tokens are referenced and referenced tokens are declared. It cannot see a raw 14px, an rgba(229,72,60,.38), or a fourth navigation duration. The codebase passes its own design lint while systematically avoiding the design system.

It is also worse than that. check:tokens is not wired into CI at all — .github/workflows/ci.yml runs typecheck, lint and test in the web job and never calls it. The single guardrail this codebase has for its design system is a package.json script that nothing runs automatically. One line in ci.yml is the cheapest item in this entire document.

02

P0 — dead ends

Severity here is simple: P0 means the app is unusable, misleading, or inaccessible. These outrank every consistency finding in this document, and the first one is not a consistency finding at all.

P0-1

The Design tab renders nothing when data fails to load

noise-lab.tsx:1158 renders a skeleton while initialLoad, then the tab while selected. Once refresh() settles — success or failure — initialLoad is false forever. If selected is undefined, which happens on any API failure, neither branch renders.

Measured — Playwright, /api/** blocked
> document.querySelector(".noise-page").innerText

"Noise Lab"   ← the screen-reader-only <h1>. Nothing else.
  The visible page is a heading, an ⓘ, a dock, and a gradient.

The only signal is a toast that deletes itself after 5,000 ms. ToastState already supports an action and this call site doesn't pass one. Combined with P0-3, a mouse user's only recovery is to reload the page.

Fix Give Design the three states every other tab has — skeleton, empty, error-with-Retry. Separate “the engine is unreachable” from “this combination isn't in the matrix”; they need different messages.
P0-2

The Queue has no empty state

An idle Queue renders zero characters — measured, #panel-queue innerText is "". At :1724 an empty bucket returns null, and :1726 composes four possibly-empty sections with nothing behind them.

Library and Releases both render an EmptyState in exactly this situation, so the app disagrees with itself about whether “nothing here” deserves an explanation. Side by side, Releases explains itself and Queue is a blank page under a live-looking green dot reading “Idle · Synced just now”. This was Phase 3 item 4 of the last audit.

Fix An EmptyState whose action points at Design — the queue is empty because nothing has been rendered, and rendering something is the next step.
P0-3

No tab can be refreshed with a mouse

usePullRefresh binds touch events only. Releases receives an onRefresh prop that reaches ReleaseDetail and fires only after a successful save — ReleaseList never calls it. The round refresh button the last audit recorded on Releases is gone, so pointer refresh is now at zero across the entire app.

The brand value was settled at #e2483b last time for continuity of focus rings and selected states. That reasoning holds and is untouched here: #e2483b is fine as a stroke. It cannot carry white text at 13px. Those are two jobs and they need two values.

P0-5

Roles that promise behaviour the widgets don't have

Three overflow menus declare role="menu" with no arrow keys, no focus move, and no focus restore. The remove sheet declares role="dialog" aria-modal="true" with no focus trap — so focus tabs straight out into the page the dialog claims to have made inert.

Worth the contrast: radioArrowHandler at :194 implements roving tabIndex and arrow keys correctly for the segmented controls. The app knows how to do this; it just hasn't where it announced that it would. Declaring the role and omitting the interaction is worse than a plain <div>, because assistive tech states a contract the widget doesn't honour.

P0-6

The splash screen says a different product name

layout.tsx:5 and the <h1> say Noise Lab. The intro wordmark — the first thing every user sees, at clamp(22px, 6vw, 32px) — says Noise Labs. One character, maximum prominence, thirty seconds to fix.

03

P1 — the primitives went in shallow

Phase 2 built the right components. Adoption stopped at the narrowest call that compiled, and in one case the collapse went far enough to delete the meaning the component existed to carry.

P1-1

StatusPill and Chip are the same component, so status is invisible

globals.css:111 gives .chip and .status-pill one shared base rule. Line 114 then declares .chip-active, .status-pill-active with exactly the two values the base rule already set. .status-pill-active is a no-op.

At :1699 a Queue card renders its status pill and its metadata chips in the same flex row. So “Rendering” is pixel-identical to “white” and “mid”. The most important word on the Queue tab has no more visual weight than a parameter label. Only success and danger are distinct; active, queued, rendering and pending all land on neutral.

Fix Give active a real tone — the --link family already means “in progress” for the sync dot — and let a pill differ from a chip in weight or shape. Type state as the union it's already being cast to.
P1-2

Every empty state is a place the next action is knowable, and none say it

Three EmptyState call sites, all title-only. The result on screen is a 180px white slab holding one line of centred bold grey — which is why the empty Library and empty Releases read as broken rather than ready and waiting.

The copy is in three voices, too: “No rendered files found.” — systems language, and “files” appears nowhere else in the UI, which says masters and tracks — alongside “No releases yet.” and “No art yet — generate a seed below.”

P1-3

One gesture, three durations, and the motion tokens sit unused

ElementTiming
.panel-show.32s cubic-bezier(.2,.8,.25,1)
.tab-lens.38s cubic-bezier(.3,1.35,.4,1)
.dock-tab colourvar(--dur-nav) — with ease, not --ease-nav

--dur-nav and --ease-nav were added for exactly this and have two call sites in the whole codebase, neither of which is the panel transition or the lens. The token didn't replace the opinions — it became a fourth one. The incoming panel still rises with no paired fade-out, so the transition is a cut with a slide on the end.

P1-4

Two styling systems, and one component that escaped both

Tailwind is loaded alongside the CSS layer and used in scattered places. Most are incidental layout utilities. One is not: the SEO-name review panel at :1363 is built entirely from Tailwind utilities, with rounded-xl — 12px, not one of the four radius tokens — its own border, its own spacing, and text-[10px].

It is the only surface in the app outside the design system in both directions: it uses neither the CSS layer nor the primitives. A third channel exists too — the app's typeface, the most global design decision in the product, is an inline style attribute on <main>.

P1-5

The type scale can't be converted mechanically

This is why P1 stalled, and it's worth naming so it doesn't stall again. Four of the eight raw sizes — 14, 16, 18, 26 — have no equivalent in a scale that jumps 13 → 15 → 17 → 21 → 30. Someone has to decide whether .section-title at 14 becomes 12 or 15, and whether .panel-heading h2 at 26 becomes 21 or 30.

That's five or six judgement calls. Once made, the remaining ~40 sites are mechanical — but nobody can start until they're made, so they're in the decisions list below.

P2 — navigation, layout, drift

P2-1

Two routing models, unchanged

Phase 4 was never started. Hash values measured while clicking each tab:

Design and Queue share the empty hash, so they are indistinguishable in history and neither is deep-linkable. libraryReturnTab and its guess are still there. Panels still render in design, library, queue, releases order against a dock in design, queue, library, releases order, so keyboard and screen-reader traversal still disagree with the screen. Scroll is still reset to 0 on every switch rather than persisted per tab.

P2-2

The dock sits on top of live controls

Confirmed at both viewports. At 1280×900 the glass bar floats directly over the Balance segmented control, and because .glassbar is translucent with no scrim, the control's segments are legible through the bar. .noise-page reserves bottom padding for the dock's height, which handles the end of the page but not a floating translucent object parked over an interactive row mid-scroll.

P2-3

There is no desktop layout

At 1280×900 the app is the 390px mobile layout centred in a 660px column, with a bottom-centre floating dock and roughly 1,000px of empty gradient below the fold on three of four tabs. The empty Library at desktop is one 200px white slab and an otherwise blank screen.

This is a console for browsing a 144-variant matrix and ~37GB of published renders. A two-pane layout — list left, detail right, dock promoted to a rail — is the largest single design win available, and the only item here that is a product decision rather than a cleanup.

P2-4

Reduced motion is half-covered

The media block disables the intro, the bell, the title transition, the refresh spin and the skeleton sheen. It does not disable .panel-show — which fires on every tab change — or .track-highlight, the :active transforms, or, most importantly, .queue-sync-dot.is-active, an infinite pulse animation. A user who asked the OS to stop motion still gets a permanently animating dot.

P2-5

Batch rendering is dead code, and other sediment

queue(ids, label) branches on "one" | "pilot" | "full", builds two selector shapes, and composes a toast reading “Full matrix (144 variants) sent to the GitHub Actions renderer.” The only call site is "one". No UI anywhere triggers a pilot or full render.

Alongside it: .queue-link, .queue-section and .panel are referenced in markup and defined nowhere; .card-padding-sm is the mirror image, defined and never used. Small individually — collectively they're what makes the next person distrust the stylesheet.

P2-6

Two sync captions, still

HeaderSyncCaption serves Library; inline markup at :1192 serves Queue. Different components, different classes, different copy. globals.css:278 is a selector whose entire purpose is to override the Queue caption's size and margin back to the Library caption's when it appears in the header — the hand-alignment those four micro-PRs were performing, now frozen into CSS.

Fix One <SyncStatus> deletes that rule, both implementations, and the entire class of follow-up ticket.

Decisions needed from Austin

Devin should not guess these — each one changes what the tokens say.

  1. Brand red for filled buttons. #e2483b gives white text 4.02:1 and fails AA. Add a darker --brand-ink for filled buttons while --brand keeps strokes and selection — or accept the contrast. Recommendation — add --brand-ink; the existing --brand-pressed #c4392b already reaches 5.9:1.

07

What is good, and must survive

Worth stating, because a token refactor can flatten these by accident.

  • Zero hex outside :root — the last audit's headline criterion, met exactly. The token block is well-organised and well-named.
  • lib/queue-strings.ts — a real centralised copy layer, and the best-engineered thing in the codebase. It's the model for Phase E, and the other three tabs should adopt the pattern.
  • radioArrowHandler + GlyphSegmented — roving tabIndex, aria-checked, arrow keys and haptics, done properly. The reference implementation for Phase B item 3.
  • Skeleton coverage on all four tabs — better than most shipped apps.
  • The FX section — the EQ curve drawn on the live spectrum, the preset glyphs, the remember-previous-state toggles. The most sophisticated interaction design in the app; nothing here touches it.
  • The ambient fields, the bell mark and the intro splash — a memorable identity. The point of this audit is that the four tabs should be able to carry it.
