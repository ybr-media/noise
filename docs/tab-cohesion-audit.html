Noise Lab console · tab cohesion audit

Four tabs,four apps.

Design, Queue, Library and Releases are each well made. The set is not a product. Everything wrong with it lives in the half-second where you move between them.

12 Aug 2026 web/app/noise-lab.tsx · globals.css Reviewed at 390×844 and 1280×900
The verdict

The four tabs were built as four apps that share a stylesheet, rather than four views that share a design system.

Nothing here is ugly and no single tab reads as broken. That is precisely why the problem is easy to miss: it is invisible inside any one tab and unmissable across all four.

There is a design-token block at the top of globals.css. Four of its ten tokens — --accent, --card, --secondary, --track — are referenced zero times in the entire stylesheet. Every tab reaches past the tokens and hard-codes its own values, so every shared decision got made four separate times.

Four things change under you when you tap the dock:

  1. 01The page header changes shape. Design has none. Library grows a toolbar. Queue grows a status line. Releases grows a second heading that repeats the title already on screen.
  2. 02The card changes. Radius 26 → 24, shadow soft-and-wide → tight-and-dark, list gap 22px → 14px.
  3. 03The primary button changes colour. Brand red on Design and Releases; black on Queue.
  4. 04The way you got there changes. Two tabs are React state, two are URL routes — so Back works on half the app.

Marked = this tab disagrees with the others on a decision that should have one answer.

B1Releases prints its own name twice

The floating title says Releases. Three hundred pixels below it, the list view's own heading says Releases again at 26px/800, with a subtitle no other tab has. It is the most visible single defect in the app.

C2The same pill, built twice

Library renders Matrix 12 · white · mid · drift as fully-round 10px chips. Queue renders literally the same four strings as 8px-radius 12px chips from a different component. Same data, same user, adjacent tabs.

C4Red stops meaning one thing

The primary button class is brand red — then a single override repaints it black inside Queue cards. A user who learns red is the main action on Design un-learns it one tap later.

A1Half the app has a Back button

Design and Queue call setTab(). Library and Releases set window.location.hash. So Back returns you to the previous tab from two tabs and exits the app from the other two, and only half the app is linkable or survives a reload. The return path is a literal guess in the code: if you are on Library and press Library again, the app has decided that Back means Queue.

A7Once you scroll, nothing names where you are

The tab title is fixed and fades out above 24px of scroll. The dock is icon-only. So a scrolled user has four abstract glyphs and no words — and because the per-tab help tooltip hangs off that disappearing title, the help becomes unreachable the moment you scroll. The same Layers glyph also means "Queue" in the dock and "Create" inside Design.

The fix · layer two

Eleven components, extracted once

Each of these already exists two, three or four times. None of this changes a feature — it is the same app, spoken in one voice.

<TabPage>Owns the title, sync line, refresh control and section spacing for all four tabs. Replaces four bespoke header recipes — and deletes the duplicate Releases heading.
<SyncStatus>One size, one grey, one dot rule, one wording. Replaces Library's 11px caption and Queue's 12px dotted one, and gives Design and Releases the status they never had.
<RefreshControl>Renders both affordances: pull gesture on touch, button on pointer. Today a desktop user cannot refresh Library or Queue, and a phone user has no refresh on Releases.
<Card>One radius, one shadow, two padding sizes. Replaces soft-card and the bespoke queue-job-card.
<Chip>One radius, one size, a tone enum. Retires track-chip, queue-chip and pilot-badge — three components rendering identical data.
<StatusPill>Ready / running / failed / submitted, mapped to the semantic tokens. Retires four competing pill styles.
<Button>Primary is always brand red. Queue's black buttons become an explicit neutral variant instead of an override that silently inverts meaning.
<EmptyState>Mandatory on all four tabs. Queue currently renders nothing at all when idle.
<Banner>Info / warning / danger. Collapses the work-in-progress banner, the read-only note and the failure strip into one alert language.
<Disclosure>One open-close rule. Today there are three: native details elements, aria-expanded panels, and a route change.
<ConfirmSheet>One destructive-confirm pattern. Queue alone has two — a modal sheet and an inline double-tap that times out after three seconds.
The fix · layer three

One navigation contract

Route everything. Hash routing already works for two tabs; extend it rather than removing it, so tab becomes derived state and the browser holds the history stack.

  • All four tabs get real routes. Back always means the previous tab. Every tab is linkable and survives a reload.
  • Scroll position persists per tab instead of being shared across all four and reset on every switch.
  • Panel order matches dock order, so keyboard and screen-reader traversal stop contradicting the screen.
  • Lens and panel share one duration and curve, with a cross-fade out to pair with the fade in.
  • The dock stops sitting on live controls — it currently floats over the Balance control on desktop and lets text read through it on mobile.
  • The current tab stays named when scrolled, via dock labels or a compact sticky bar, with the help control moved off the disappearing title.
Handoff · sequence

Five phases, each shippable alone

Phases 1 and 2 are pure refactors with no intended visual change, except where the audit says the tab was wrong.

1

Token layer

Write the :root block. Replace all hex literals in the stylesheet. Delete the competing palette object in the component file and route the toast and spectrum canvas to the token source. Collapse the one-off type sizes, the lone 650 weight, and the twelve radii.

Done when grepping for hex in globals.css returns only lines inside :root; typecheck and tests pass; screenshot diffs show only the intended colour collapses.

2

Shared primitives

Extract Card, Chip, StatusPill, Button, Banner, EmptyState and Disclosure. Retire the bespoke queue card and the duplicate chip. Delete the override that repaints the primary button black. Unify the list gap and the section label.

Done when no colour or radius literals remain in the component file, and Queue and Library render identical chips for identical data.

3

Page chrome

Build TabPage, SyncStatus and RefreshControl and adopt them everywhere. Delete the duplicate Releases heading. Give every tab both refresh affordances, a status line, and a designed empty state. Move the help control off the scroll-hiding title.

Done when all four tabs refresh by pointer and by touch, all four render an empty state, and "Releases" appears exactly once on screen.

4

Navigation

Route all four tabs; derive tab from location; delete the return-tab guess. Persist scroll per tab. Reorder the panels. Unify the transition with the lens. Stop the dock occluding controls. Give the Queue tab or the Create button a distinct glyph. Settle badge semantics.

Done when Back works from all four tabs, every tab deep-links and survives reload, scroll is preserved per tab, and no control is occluded at 390px or 1280px.

5

Guardrails

A stylelint rule banning hex outside :root. A short design-language doc recording the tokens and the component inventory. Rebuild the four loading skeletons from the real components instead of hand-drawn geometry.

Done when a fifth tab cannot fork the design system without failing lint.

Before phase one

Five calls that are yours, not Devin's

These change what the tokens say, so they need answering first. One is settled; four are open.

Which red is the brand?

Four candidates were in the code: #e5483c on buttons, #e2483b on selection and focus, #ff3b30 in the unused token, #d23a2f in the play button's shadow. The three doing brand work collapse into one token, and the play button's gradient gets rebuilt from it.

Settled 13 Aug — --brand: #e2483b

Does error red equal brand red?

Right now they are the same family, which makes a failed render look like a call to action.

Recommend splitting them: --danger #c4392b

What happens to Queue's black buttons?

Either they become neutral secondary actions and Queue has no red primary, or black becomes a real app-wide neutral variant. Both are coherent; today's state is not.

Recommend neutral variant, used app-wide

One list rhythm — 22px or 14px?

Design and Library breathe at 22px; Queue and Releases run tight at 14px.

Recommend 18px as the single value

Dock labels, or a sticky title bar?

Once scrolled there is no text anywhere naming the current tab. One of the two is needed.

Needs a decision — neither exists today
Preserve

What is already right

Worth naming, because a token refactor can flatten these by accident.

  • Skeleton coverage on all four tabs is better than most shipped apps.
  • The parameter controls — roving tabindex, arrow-key navigation, aria-checked, selection haptics — are genuinely well built.
  • The overflow menu is real component reuse across Library and Queue. It proves the team can do this.
  • queue-strings.ts is a proper centralised copy layer. It is the one place in the codebase already doing what this audit asks for everywhere else. Use it as the model.
  • The ambient background and intro splash give the product a memorable identity that the tabs themselves currently fail to carry through.
